## Subnetting — Расчёт подсетей

### Формула: сколько нужно хостовых битов

Для нужного количества хостов используй формулу: **2^n - 2 ≥ требуемое_кол-во_хостов**

| Нужно хостов | Хостовых бит | Реальных адресов | Маска |
|---|---|---|---|
| 1–2 | 2 бит | 2 | /30 |
| 3–6 | 3 бит | 6 | /29 |
| 7–14 | 4 бит | 14 | /28 |
| 15–30 | 5 бит | 30 | /27 |
| 31–62 | 6 бит | 62 | /26 |
| 63–126 | 7 бит | 126 | /25 |
| 127–254 | 8 бит | 254 | /24 |

> **Пример:** нужно 7 хостов → 3 бита дают только 6 (мало) → берём **4 бита** (14 хостов).

### Сколько подсетей получится из /24

Если из /24 взять **n бит** под подсети → получится **2^n** подсетей.

**Пример:** нужно 7 хостов → 4 хостовых бита → маска /28 → из /24 взяли 4 бита под подсети → **2^4 = 16 подсетей**

| Маска подсети | Хостовых бит | Подсетей из /24 | Хостов в каждой |
|---|---|---|---|
| /25 | 7 | 2 | 126 |
| /26 | 6 | 4 | 62 |
| /27 | 5 | 8 | 30 |
| /28 | 4 | 16 | 14 |
| /29 | 3 | 32 | 6 |
| /30 | 2 | 64 | 2 |

## Subnet Mask — Перевод маски в prefix

### Частые маски которые надо знать наизусть

| Маска | Prefix | Двоичный октет |
|---|---|---|
| 255.0.0.0 | /8 | 11111111 |
| 255.255.0.0 | /16 | 11111111 |
| 255.255.128.0 | **/17** | 10000000 |
| 255.255.192.0 | /18 | 11000000 |
| 255.255.224.0 | /19 | 11100000 |
| 255.255.240.0 | /20 | 11110000 |
| 255.255.248.0 | /21 | 11111000 |
| 255.255.252.0 | /22 | 11111100 |
| 255.255.254.0 | /23 | 11111110 |
| 255.255.255.0 | /24 | 11111111 |
| 255.255.255.128 | /25 | 10000000 |
| 255.255.255.192 | /26 | 11000000 |
| 255.255.255.224 | **/27** | 11100000 |
| 255.255.255.240 | /28 | 11110000 |
| 255.255.255.248 | /29 | 11111000 |
| 255.255.255.252 | /30 | 11111100 |

### Как определить невалидную маску

Валидная маска в двоичном виде — **непрерывные единицы**, затем **непрерывные нули**.

**Невалидный пример: 255.255.249.0**
- 249 в двоичном = `11111001` — единицы прерываются нулями → **НЕВАЛИДНАЯ**

**Валидные октеты:** 0, 128, 192, 224, 240, 248, 252, 254, 255 — только они допустимы.

## Default Static Route

```bash
Router(config)# ip route 0.0.0.0 0.0.0.0 [next-hop-ip | exit-interface]
```

`ip route 0.0.0.0 0.0.0.0 209.165.200.226` означает:
- **Destination:** 0.0.0.0 (любая сеть)
- **Mask:** 0.0.0.0 (подходит любой адрес)
- **Next-hop:** 209.165.200.226

**Цель:** обеспечить маршрут для **всех пакетов, для которых нет более специфичного маршрута** в таблице маршрутизации. Это и есть "маршрут последней надежды" (gateway of last resort).

> [!important] Это НЕ "переслать все пакеты туда"
> Роутер сначала ищет самый специфичный маршрут. Default route используется только если совпадений нет.

## SSH — Что нужно настроить ДО генерации ключей

Обязательная последовательность настройки SSH:

```bash
! 1. Сначала - hostname (должен быть не default)
Router(config)# hostname R1

! 2. Обязательно - domain name (без него crypto key не работает)
R1(config)# ip domain-name cisco.com

! 3. Только теперь можно генерировать RSA ключи
R1(config)# crypto key generate rsa
How many bits in the modulus [512]: 1024

! 4. Создать пользователя
R1(config)# username admin secret cisco

! 5. Настроить VTY линии
R1(config)# line vty 0 15
R1(config-line)# transport input ssh
R1(config-line)# login local

! 6. Включить SSHv2
R1(config)# ip ssh version 2
```

**Без `ip domain-name` команда `crypto key generate rsa` не выполнится.** Это самое частое на экзаменах.

## Route Summarization (Суммаризация маршрутов)

**Суммаризация** — объединение нескольких подсетей в одно общее объявление маршрута.

**Пример:** вместо четырёх маршрутов:
- 192.168.0.0/24
- 192.168.1.0/24
- 192.168.2.0/24
- 192.168.3.0/24

Роутер может объявить один: **192.168.0.0/22** — это и есть суммаризация.

**Зачем:** уменьшает размер таблиц маршрутизации, снижает нагрузку на протоколы маршрутизации.

Не путай с VLSM (разные маски для разных подсетей) — это другое.

## Port Security — Режимы нарушения (Violation Modes)

| Режим | Что делает при нарушении | Лог | Порт отключается |
|---|---|---|---|
| **protect** | Дропает пакеты с неизвестных MAC | ❌ Нет | ❌ Нет |
| **restrict** | Дропает пакеты + пишет в лог + SNMP trap | ✅ Да | ❌ Нет |
| **shutdown** | Порт уходит в **err-disabled** | ✅ Да | ✅ Да |

**Default режим = shutdown.**

```bash
! Включить port security
SW(config-if)# switchport port-security

! Установить максимум MAC адресов
SW(config-if)# switchport port-security maximum 2

! Выбрать режим нарушения
SW(config-if)# switchport port-security violation restrict

! Sticky - автоматически учить MAC и сохранять в running-config
SW(config-if)# switchport port-security mac-address sticky
```

### Что делает команда `mac-address sticky`

Коммутатор **автоматически узнаёт** MAC-адрес подключённого устройства и **добавляет его в running-config** как статический. При `copy running-config startup-config` — сохраняется постоянно. Без sticky — MAC учится динамически и теряется при перезагрузке.

## HSRP — Hot Standby Router Protocol

### Версии v1 и v2

| Параметр | HSRPv1 | HSRPv2 |
|---|---|---|
| Group range | 0 – 255 | 0 – **4095** |
| Multicast | 224.0.0.2 | **224.0.0.102** |
| Virtual MAC | **0000.0C07.AC**xx | **0000.0C9F.F**xxx |
| Таймер Hello | 3 сек | 3 сек |
| Таймер Hold | 10 сек | 10 сек |

> xx и xxx = номер группы в шестнадцатеричном виде

### Состояния HSRP
`Initial` → `Learn` → `Listen` → `Speak` → `Standby` → **`Active`**

### Ключевые факты
- **Active роутер** = наибольший приоритет (default 100). Обрабатывает весь трафик.
- **Standby роутер** = следующий по приоритету. Ждёт сбоя.
- **preempt** — позволяет роутеру вернуть роль Active после восстановления.
- Порт: **UDP 1985**
- Cisco-only протокол

```bash
R1(config-if)# standby 1 ip 192.168.1.1          ! виртуальный IP
R1(config-if)# standby 1 priority 110             ! приоритет (default 100)
R1(config-if)# standby 1 preempt                  ! вернуть роль Active
R1(config-if)# standby version 2                  ! включить v2
```

## Native VLAN — Важный нюанс

**Native VLAN ДОЛЖЕН совпадать** на обоих концах trunk-линка.

- Если не совпадает → Cisco выдаёт предупреждение в консоль
- Трафик native VLAN идёт **без тега** (untagged) на trunk-порту
- Default native VLAN = **VLAN 1**
- Best practice: изменить native VLAN на неиспользуемый (например VLAN 999) для безопасности

```bash
SW(config-if)# switchport trunk native vlan 999
```

> [!danger] Ловушка на экзамене
> Утверждение "Native VLAN не должен совпадать на обоих концах" — **ЛОЖЬ (FALSE)**. Он ДОЛЖЕН совпадать.

## 802.1Q Tag — Структура тега VLAN

Тег 802.1Q добавляет **4 байта (32 бита)** в Ethernet фрейм:

| Поле | Размер | Описание |
|---|---|---|
| TPID | 16 бит | Тип протокола = 0x8100 (признак тега) |
| PCP | 3 бита | Priority Code Point — приоритет QoS |
| DEI | 1 бит | Drop Eligible Indicator |
| **VID** | **12 бит** | **VLAN ID — номер VLAN** |

**12 бит VID** → значения 0–4095 → **4094 возможных VLAN** (0 и 4095 зарезервированы).

## WPA2 Enterprise vs WPA2 Personal

| | WPA2 Personal (PSK) | WPA2 Enterprise |
|---|---|---|
| Аутентификация | PSK (Pre-Shared Key) — один пароль для всех | **802.1X** — каждый пользователь со своим логином |
| Шифрование | AES (или TKIP) | **AES (CCMP)** |
| Сервер | Не нужен | Нужен **RADIUS-сервер** |
| Применение | Дом, малый офис | Корпоративные сети |

**WPA2 Enterprise = AES + 802.1X** — это стандарт для корпоративных WLAN.

### Эволюция безопасности Wi-Fi
- **WEP** — устарел, легко взламывается (RC4, статичный ключ)
- **WPA** — улучшение WEP (TKIP шифрование)
- **WPA2** — текущий стандарт (**AES-CCMP**, 802.1X или PSK)
- **WPA3** — новейший (SAE вместо PSK, защита от перебора паролей)

## Wi-Fi — Частоты и каналы

### Диапазоны частот
- **2.4 GHz** — большая дальность, хуже проходит через стены, больше помех (Bluetooth, микроволновки)
- **5 GHz** — быстрее, меньше помех, меньше дальность
- **6 GHz** — только Wi-Fi 6E (802.11ax)

**Стандартные диапазоны Wi-Fi: 2.4 GHz и 5 GHz**

### Неперекрывающиеся каналы 2.4 GHz
Каналы **1, 6, 11** — единственные три, которые не перекрываются. Используются рядом стоящими AP чтобы избежать интерференции.

## IPv6 — Типы адресов по маршрутизируемости

| Тип | Диапазон | Маршрутизируется в интернете |
|---|---|---|
| **Global Unicast (GUA)** | 2000::/3 | ✅ Да — публичные адреса |
| Unique Local (ULA) | fc00::/7 | ❌ Нет — аналог RFC 1918 |
| Link-Local | fe80::/10 | ❌ Нет — только в сегменте |

**Только Global Unicast адреса маршрутизируются в интернете.**

### Как выглядит Link-Local адрес
- Всегда начинается с **fe80::** (первые 10 бит = 1111 1110 10)
- Пример корректного: `fe80::8fc0:80ef:8e83:a079`
- FC07::1 и FD07::1 — это Unique Local (fc/fd), не Link-Local
- FE80:1 — технически начало верное но слишком короткий формат

## DHCP — Обновление аренды (Lease Renewal)

### Полный жизненный цикл аренды

| Момент | Что происходит | Тип сообщения |
|---|---|---|
| Первое получение | DORA процесс | DISCOVER → OFFER → **REQUEST** → ACK |
| 50% срока аренды | Клиент пытается обновить у **того же** сервера | **DHCPREQUEST** (unicast) |
| 87.5% срока аренды | Клиент пытается обновить у **любого** сервера | **DHCPREQUEST** (broadcast) |
| Принятие OFFER | Клиент принимает предложенный IP | **broadcast DHCPREQUEST** |
| Истечение аренды | Клиент перестаёт использовать IP | — |

> [!important] Частый вопрос
> - "Что отправляет клиент чтобы **принять** предложение от сервера?" → **broadcast DHCPREQUEST**
> - "Что отправляет клиент когда **аренда истекает**?" → **DHCPREQUEST** (для обновления)

## Физические топологии — Отличия

| Топология | Вид | Особенность |
|---|---|---|
| **Bus (шина)** | Все устройства на одном кабеле (одна линия) | Обрыв = вся сеть падает |
| **Star (звезда)** | Все устройства к центральному узлу | Обрыв одного не влияет на остальных |
| **Extended Star** | Звёзды соединённые между собой | Иерархическая структура |
| **Ring (кольцо)** | Устройства в кольце | Данные идут по кругу |
| **Mesh (ячеистая)** | Каждое устройство со многими другими | Максимальная отказоустойчивость |
| **Full Mesh** | Каждое с каждым | n(n-1)/2 соединений |

**Bus = одна линия, все на ней** — самая лёгкая для узнавания.

## PDU — Единицы данных на каждом уровне

| Уровень OSI | Уровень TCP/IP | PDU |
|---|---|---|
| 7 Application | Application | **Data** |
| 6 Presentation | Application | **Data** |
| 5 Session | Application | **Data** |
| **4 Transport** | **Transport** | **Segment** |
| 3 Network | Internet | **Packet** |
| 2 Data Link | Network Access | **Frame** |
| 1 Physical | Network Access | **Bits** |

> Transport Layer = **Segment** — это один из самых частых вопросов.
